# IPC(Inter-Process Communication) 기법

###  1. Pipe & FIFO
   + __전송 단위__ : 연속된 바이트 스트림 (경계 없음)
   + __통신 형태__ : 단방향 (1:1)
   + __복사 비용__ : 2회 (Ueser -> Kernel -> User)
   + __속도/처리량__ : 보통
   + __동기화 필요__ : 불필요(커널 자동 동기화)
   + __주요 특징__ :
     + 직관적이고 구조가 단순함
     + FIFO 구조
     + 부모-자식 간 통신(익명 파이프)
   + __주요 목적__ : 쉘 파이프라인('|'), 단순 명령 전달, 가벼운 단방향 스트리밍
   
### 2. Shared Memory
   + __전송 단위__ : 원시 메모리 영역 (구조체, 버퍼 등)
   + __통신 형태__ : 메모리 직접 공유 (N:M)
   + __복사 비용__ : 0회
   + __속도/처리량__ : 최상(가장 빠름, 대역폭 최대)
   + __동기화 필요__ : 필수 구현(세마포어, 뮤텍스 등) 
   + __주요 특징__ :
     + 커널 개입 없는 직접 메모리 접근
     + 동기화 부재 시 Race Condition 발생
     + 고성능 임베디드 필수 기술
   + __주요 목적__ : 대용량 영상/카메라 프레임, 초고속 데이터 스트림, 대용량 버퍼 공유
   
### 3. Message Queue
   + __전송 단위__ : 정형 메시지 블록(메시지 경계 보존) -> 별도의 파싱(스트림 슬라이싱) 불필요
   + __통신 형태__ : 단방향 / 다자간 큐 (1:1, 1:N, N:M)
   + __복사 비용__ : 2회 (Ueser -> Kernel -> User)
   + __속도/처리량__ : 보통
   + __동기화 필요__ : 불필요(커널 큐 자동 관리)
   + __주요 특징__ :
     + 우선순위 처리 지원 - FIFO와 달리 높은 우선순위(priority)을 가진 메시지 부터 확인 
     + 비동시 메시징 가능 - 수신자가 준비되지 않아도 큐의 크기 한도 내에서 메시지를 쌓을 수 있음
     + 시스템 설정에 따른 용량 제한 존재
   + __주요 목적__ : 긴급 경고/이벤트 전송, 우선순위 기반 제어 신호, 프로세스 간 작업 요청 패킷
   
### 4. Socket
   + __전송 단위__ : 바이트 스트림(TCP) 또는 패킷(UDP)
   + __통신 형태__ : 양방향(Full-Duplex) (1:N 클라이언트-서버)
   + __복사 비용__ : 2회 (Ueser -> Kernel -> User)
   + __속도/처리량__ : 빠름(UDS) ~ 보통(NetWork)
   + __동기화 필요__ : 불필요(커너 버퍼 자동 관리)
   + __주요 특징__ :
     + 원격(다른 컴퓨터) 통신 지원 (유일)
     + UDS는 파일 디스크립터 전달 가능
     + 네트워크 코드로 손쉬운 확장
   + __주요 목적__ : 1:N 클라이언트-서버 모델, 마이크로 서비스 아키텍처, 로컬/원격 네트워크 통신
   
### 5. Signal
   + __전송 단위__ : 시그널 번호(ID) (실시간 시그널 : 정수값 추가)
   + __통신 형태__ : 비동기 이벤트 알림 (SW 인터럽트)
   + __복사 비용__ : 없음 (커널 제어 수준)
   + __속도/처리량__ : 반응속고 즉각정 (처리량 극히 낮음)
   + __동기화 필요__ : 해당 없음 (핸들러 재진입 안정성 주의)
   + __주요 특징__ :
     + 프로세스 코드 흐름을 강제 중간 후 핸들러 실행
     + 표준 시그널은 중복시 유실 가능 - 표준 시그널 (1~31번 신호)
     + 데이터 전송이 아닌 이벤트 통시 전용
   + __주요 목적__ : 프로세스 종료/재시작(SIGTERM, SIGHUP), 자식 프로세스 종료 감지(SIHCHLD), 비동기 인터럽트 트리거

## sizeof vs strlen()
+ __sizeof__ : 해당 변수나 배열에 __할당된 총 메모리 크리(바이트)__ 반환
+ __srtlen()__ : 메모리 시작 주소부터 '\0' 문자가 나올 때까지 순회하며 문자 개수를 센다
+ 예시 
  + char arr[20] = "hello";
    + sizeof(arr) : 배열의 전체 메모리 공간 크기 __20__
    + strlen(arr) : 널 문자 앞까지 실제 문자 수 __5__
  + char *ptr = "hello";
    + sizeof(ptr) : 문자열의 크기가 아닌 __포인트 변수의 크기 (64비트 시스템 = 8바이트)__
    + strlen(ptr): 가리키는 문자열의 실제 길이 __5__

| 구분 | sizeof 연산자 | strlen() 함수 |
| :---: | :---: | :---: | 
| 종류 | 연산자 (Operator) | 표준 라이브러리 함수 |
| 헤더파일 | 불필요 | <string.h>(C) / <cstring> (C++) |
| 평가 시점| 컴파일 시점 | 런타임 시점 |
| 측정 대상 | 변수/타입이 메모리에 차지하는 바이트 크기 | 문자열에서 \0(널 문자) 직전까지 문자 개수 |
| 널 문자 | 메모리네 포함되어 바이트 수에 포함 | 포함하지 않음 |
| 인자 | 모든 타입, 변수, 배열, 구조체 등 | 문자열 포인터(const char *) |

## 메모리와 저장공간
### 1. 물리적 하드웨어 저장장치
| 구분 | Disk (SSD / HHD) | RAM (주기억장치) |
| :---: | :---: | :---: |
| 역할 | 파일, OS등을 영구적으로 저장한느 공간 | CPU가 실행할 코드와 데이터를 올려두는 공간 |
| 휘발성 | 비휘발성 | 휘발성 |
| 속도 | 상대적으로 느림 | 디스크보다 수백~수천 배 빠름 |
| 용량/가격 | 512GB ~ 수 TB (저렴) | 8GB ~ 64GB (비쌈) |
| 내용 | 프로그램 파일, 사진, 문서 등 | 현재 실행 중인 프로그램의 코드와 데이터 |

### 2. 논리적 공간
+ __user space__ : 일반적인 프로그램이 차지하는 영역
  + 프로세스마다 독립적인 공간을 할당
  + 4가지 구조:
    + code (text) : 컴파일된 기계어 명령어 -> Read-Only 영역
    + Data / BSS : Global 변수나 Static 변수가 저장되는 곳 -> 프로그램 시작시 항달, 종료시 해제
    + Heap : 실행 중에 동적으로 크기를 늘려 쓰는 곳 (malloc, new) -> 낮은 곳에서 높은 주소로 할당
    + Stack : 함수가 호출될 때 생기는 지역 변수, 매개변수, 함수 호출 복귀 주소 저장 -> 높은 주소에서 낮은 주소 할당
+ __kernel space__ : 커널의 공유 공간
  + 하드웨어 제어, 프로세스 스케줄링, 메모리 분배 등 핵심 코드와 데이터 포함
  + user space 프로그햄은 커널 메모리에 __직접 접근할 수 없음__
    + 커널 메모리를 억지로 읽거나 쓰면 OS가 강제 종료시키며 __Segmentation Fault__ 발생
    + 일반 프로그램은 시 system call 으로 통해 커널 메모리에 접근 요청 가능

### 3. 프로그램 동작 흐름
1. __Disk__ : start.exe 파일을 읽음
2. __kernel space__ : OS가 커널 메모리에 해당 프로세스를 관리할 메타이터(PCB)를 등록
3. __user space__ : 프로그램을 위한 가상 메모리 공간(Code, Data, Heap, Stack)이 배정됨
4. __RAM__ : 프로그램 실행에 필요한 코드와 텍스트가 RAM에 적재되며 CPU가 처리함
