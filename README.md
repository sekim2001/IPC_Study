# IPC(Inter-Process Communication) 기법

1. Pipe & FIFO
   + __전송 단위__ : 연속된 바이트 스트림 (경계 없음)
   + __통신 형태__ : 단방향 (1:1)
   + __복사 비용__ : 2회 (Ueser -> Kernel -> User)
   + __속도/처리량__ : 보통
   + __동기화 필요__ : 불필요(커널 자동 동기화)
   + __주요 특징__ :
     + 직관적이고 구조가 단순함
     + FIFO 구조
     + 부모-자식 간 통신(익명 파이프)
   + __주요 목적__ : 단순 데이터 파이프 라인, 명령어 간 출력 전달, 가벼운 단방향 스트리밍
   
2. Shared Memory
   + __전송 단위__ : 원시 메모리 영역 (구조체, 버퍼 등)
   + __통신 형태__ : 메모리 직접 공유 (N:M)
   + __복사 비용__ : 0회
   + __속도/처리량__ : 최상(가장 빠름, 대역폭 최대)
   + __동기화 필요__ : 필수 구현(세마포어, 뮤텍스 등) 
   + __주요 특징__ :
     + 커널 개입 없는 직접 메모리 접근
     + 동기화 부재 시 Race Condition 발생
     + 고성능 임베디드 필수 기술
   + __주요 목적__ : 대용량 영상/카메라 프레임, 초고속 센서 로그 공유, 대규모 공유 캐시
   
4. Message Queue
   + __전송 단위__ : 정형 메시지 블록(메시지 경계 보존)
   + __통신 형태__ : 단방향 / 다자간 큐 (1:1, 1:N, N:M)
   + __복사 비용__ : 2회 (Ueser -> Kernel -> User)
   + __속도/처리량__ : 보통
   + __동기화 필요__ : 불필요(커널 큐 자동 관리)
   + __주요 특징__ :
     + 우선순위 처리 지원
     + 비동시 메시징 가능
     + 시스템 설정에 따른 용량 제한 존재
   + __주요 목적__ : 긴급 경고/이벤트 전송, 우선순위 기반 제어 신호, 프로세스 간 작업 요청 패킷
   
5. Socket
   + __전송 단위__ : 바이트 스트림(TCP) 또는 패킷(UDP)
   + __통신 형태__ : 양방향(Full-Duplex) (1:N 클라이언트-서버)
   + __복사 비용__ : 2회 (Ueser -> Kernel -> User)
   + __속도/처리량__ : 빠름(UDS) ~ 보통(NetWork)
   + __동기화 필요__ : 불필요(커너 버퍼 자동 관리)
   + __주요 특징__ :
     + 원격(다른 컴퓨터) 통신 지원 (유일)
     + UDS는 파일 디스크립터 전달 가능
     + 네트워크 코드로 손쉬운 확장
   + __주요 목적__ : 1:N 클라이언트-서버 모델, 마이크로 서비스 아키텍처, 로컬/원격 네트워크 통신
   
6. Signal
   + __전송 단위__ : 시그널 번호(ID) (실시간 시그널 : 정수값 추가)
   + __통신 형태__ : 비동기 이벤트 알림 (SW 인터럽트)
   + __복사 비용__ : 없음 (커널 제어 수준)
   + __속도/처리량__ : 반응속고 즉각정 (처리량 극히 낮음)
   + __동기화 필요__ : 해당 없음 (핸들러 재진입 안정성 주의)
   + __주요 특징__ :
     + 프로세스 코드 흐름을 강제 중간 후 핸들러 실행
     + 표준 시그널은 중복시 유실 가능
     + 데이터 전송이 아닌 이벤트 통시 전용
   + __주요 목적__ : 프로세스 종료/재시작(SIGTERM, SIGHUP), 자식 프로세스 종료 감지(SIHCHLD), 비동기 인터럽트 트리거
